# Risk-Based Vulnerability Management (RBVM) Engine
**Capstone Initial Report and Exploratory Data Analysis (EDA)**

---

## 1. Project Overview & Problem Statement
Current enterprise security workflows suffer from severe **alert fatigue** generated by vulnerability scanners (e.g., Qualys, Tenable). Traditional triage relies heavily on CVSS (Common Vulnerability Scoring System) base scores, leading organizations to attempt patching thousands of "High" and "Critical" vulnerabilities that pose no operational threat.

This project builds a data-driven **Risk-Based Vulnerability Management (RBVM) Engine**. By combining scanner telemetry with threat intelligence (EPSS, CISA KEV) and asset criticality, the model automatically routes vulnerabilities into risk-based SLA tiers—identifying the subset of vulnerabilities requiring immediate 24-hour remediation.

---

## 2. Dataset & Data Cleaning
The dataset synthesizes typical enterprise scanner records ($N=5,000$), threat feeds, and asset registry metadata.

### Data Cleaning Summary:
* **Missing Value Imputation:** $3\%$ of CVSS records contained missing values due to scanner parse errors. These were imputed using median CVSS scores grouped by `asset_criticality`.
* **Anomaly & Outlier Handling:** Evaluated extreme values in `days_open`. Kept legitimate long-tail unpatched vulnerabilities as valid enterprise conditions.
* **Duplicate Scrubbing:** Verified zero duplicated unique vulnerability IDs.

---

## 3. Feature Engineering
To move beyond static CVSS scores, three engineered features were created:
1. **`risk_composite_score`**: Continuous variable representing $\text{CVSS} \times \text{EPSS} \times \text{Exposure Weight}$ ($1.5\times$ multiplier for internet-facing assets).
2. **`is_high_threat`**: Boolean flag indicating an actively exploited vulnerability (CISA KEV) paired with an EPSS $> 0.10$.
3. **`asset_criticality_num`**: Ordinal mapping of asset tiers ($\text{Low}=1$, $\text{Medium}=2$, $\text{High}=3$, $\text{Critical}=4$).

---

## 4. Exploratory Data Analysis (EDA) & Key Findings
* **EPSS Right-Skew:** Exploit Prediction Scoring System (EPSS) scores show a heavy right skew; less than $10\%$ of vulnerabilities exhibit a probability $> 0.35$ of exploit activity in the wild.
* **CVSS vs. Threat Intelligence Misalignment:** Scatter plot analysis confirms that many CVSS 9.0+ vulnerabilities lack public exploit activity, whereas several CVSS 6.0–7.5 vulnerabilities are actively targeted in the wild (CISA KEV listed).
* **Asset Exposure Factor:** Internet-facing assets accounted for over $70\%$ of high-composite risk scores despite representing only $25\%$ of total asset count.

---

## 5. Baseline Modeling & Evaluation
A **Decision Tree Classifier** (`max_depth=5`) was selected as the baseline model due to its transparency, deterministic rule extraction capability, and alignment with cybersecurity SLA routing.

### Primary Evaluation Metric: **Recall** and **ROC-AUC**
* **Rationale:** In vulnerability prioritization, a **False Negative** (failing to flag an actively exploited, critical vulnerability for 24h patching) results in a potential breach. **Recall** measures the model's ability to catch all true high-risk threats, making it the primary optimization metric.

### Baseline Results:
* **Recall (Class 1 - Action Required):** $\sim 0.94$
* **Precision (Class 1):** $\sim 0.88$
* **ROC-AUC Score:** $\sim 0.96$

The baseline model effectively isolates high-risk threats, significantly reducing the standard patching burden by over $75\%$ while maintaining high coverage over actionable threats.
